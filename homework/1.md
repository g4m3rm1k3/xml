## Lesson 1: Modular Design (Breaking Monoliths into Domains)
### Concept (What It Is)
Modular design means splitting code into independent, reusable parts (modules) based on responsibilities. In DDD (which you watched), this aligns with "bounded contexts"—group code by domain (e.g., Parsing domain separate from Simulation). In Python, use files/folders for modules (e.g., `parser.py`), imports, and classes/functions with clear interfaces. Avoid "god classes" (one file doing everything).

### Rationale (Why It Matters)
- **Scalability:** Your hacked projects work now, but at 500k lines? Chaos. Modules reduce "blast radius"—change one without breaking all.
- **Maintainability:** Easier debugging (test one module), collaboration (assign domains), and reuse (e.g., reuse parser in another CNC tool).
- **Real-World Tie-In:** In CNC, a buggy simulator shouldn't crash the editor. Patterns like SOLID's Single Responsibility Principle (SRP) enforce this—one class/module, one job.
- **Trade-Offs:** More files = more imports (con: navigation overhead; pro: use IDEs like VS Code for quick jumps). "It depends": For tiny scripts, single-file is fine; for apps, modularize early.
- **Common Pitfalls:** Tight coupling (modules depend too much on each other)—fix with interfaces (e.g., abstract classes).

### Implementation (How to Apply)
1. Identify domains from BRD: E.g., Parsing (text → objects), Simulation (execute lines), GUI (display).
2. Create folders/files: `src/parser.py`, `src/simulator.py`, `src/gui.py`.
3. Use imports: In `main.py`, `from src.parser import parse_gcode`.
4. Enforce boundaries: No direct GUI calls in parser—pass data via functions.
5. Example (From Our App):
   - Monolith: All in one file.
   - Modular: `parser.py` has `parse_gcode(text)` returning lines; `simulator.py` has `execute_line(state, line)`; GUI calls them.

**Before/After Table:**

| Aspect | Monolith (Bad) | Modular (Good) | Why Better |
|--------|----------------|----------------|------------|
| Change a parse rule | Edit huge file, risk breaking sim | Edit parser.py only | Low risk, fast |
| Test simulation | Run whole app | Import and test simulator.py alone | Isolated, quicker |
